Your #1 requirement is “local-first” + PST privacy. Pinecone is primarily a managed cloud vector DB, which means your embeddings + metadata live off-device unless you add extra architecture. (That’s a big deal when the data is literally your email history.)

6) PST ingestion & parsing pipeline
Constraints

PSTs can be large, encrypted, or malformed.

You need: streaming, checkpoints, idempotency, resumability.

Worker parsing approach

Worker downloads PST from object storage to ephemeral disk.

Run Tika extraction to emit one record per email.

Transform into canonical schema.

Write to Postgres in batches (e.g., 500 messages/txn).

Save checkpoint every N messages (last processed embedded path / UID).

Persist raw bodies optionally as object store blobs (or store clean text only).

Encrypted PST handling

Detect encryption early.

Fail gracefully with actionable guidance (user must supply unencrypted PST or export to a supported format).

Never ask for user’s PST password unless you have a secure design for handling it (recommended: avoid).

7) Preprocessing rules (quality-critical)
Normalization

subject_norm: strip RE:, FW:, [EXTERNAL], whitespace normalization

direction: infer from mailbox identity + folder + sender hash

Cleaning

Remove signature blocks (pattern/heuristics)

Collapse quoted replies (store separately if you need thread-level summarization)

Deduplicate:

content hash of subject_norm + cleaned_body + ts_bucket + participants_hash

keep canonical copy

Thread reconstruction

Primary: PST conversation metadata if accessible

Fallback: thread_key = hash(subject_norm + sorted(participants) + time_window_bucket)

8) Embedding & indexing pipeline
Chunking

Chunk cleaned body to ~400–800 tokens with overlap ~50–100 tokens.

Hard-drop:

huge boilerplate

repetitive quoted blocks

auto-generated disclaimers (optional filter)

Idempotent upsert

chunk_id deterministic from {message_id, chunk_index, content_hash}

Re-run safe (upsert overwrites).
